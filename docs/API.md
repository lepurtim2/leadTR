# LeadTR — API Contract

## 1. API principles

Base URL example:

```text
/api/v1
```

All API responses should have predictable schemas.

All list endpoints should paginate.

Expensive operations should become asynchronous jobs.

## 2. Authentication

Dashboard authentication may use a managed auth provider or application-native auth.

Public API access uses API keys.

Never expose secret API keys in logs.

API key storage should use hashing or another safe storage design so the raw secret is not recoverable from the database.

```text
GET /api/v1/businesses?category=dentist&province=istanbul&district=kadikoy&has_booking=false&min_rating=4.3
```

## 4. Business detail

```http
GET /api/v1/businesses/:id
```

Return:
- canonical business identity
- categories
- locations
- business contacts according to product permissions
- website
- social links
- business attributes
- quality signals
- freshness metadata

Do not expose raw source payloads by default.

## 5. Search count

```http
GET /api/v1/businesses/count
```

Useful for UI filter previews.

Must have rate limits because count queries can be expensive.

## 6. Export

### Create export

```http
POST /api/v1/exports
```

Payload contains the saved query/filter definition.

Response:

```json
{
  "id": "export_id",
  "status": "queued"
}
```

### Check export

```http
GET /api/v1/exports/:id
```

### Download

```http
GET /api/v1/exports/:id/download
```

Exports should be generated by workers and stored in object storage.

## 7. API usage

```http
GET /api/v1/account/usage
```

Return:
- current plan
- credits remaining
- requests used
- exports used
- reset date

## 8. API keys

```http
POST   /api/v1/api-keys
GET    /api/v1/api-keys
DELETE /api/v1/api-keys/:id
```

Show the raw key only once at creation time.

## 9. Saved searches

```http
POST   /api/v1/saved-searches
GET    /api/v1/saved-searches
GET    /api/v1/saved-searches/:id
DELETE /api/v1/saved-searches/:id
```

## 10. Admin API

```text
POST /api/v1/admin/ingestion-runs
GET  /api/v1/admin/ingestion-runs
GET  /api/v1/admin/jobs
GET  /api/v1/admin/data-quality
POST /api/v1/admin/reindex
POST /api/v1/admin/recalculate-scores
```

Admin endpoints require explicit authorization.

## 11. Error format

Recommended:

```json
{
  "error": {
    "code": "INVALID_FILTER",
    "message": "The supplied filter is invalid.",
    "request_id": "..."
  }
}
```

Never return stack traces to customers.

## 12. Rate limits

Starting example:

```text
Dashboard:
60 requests/minute/user

Public API:
plan based

Admin:
separate higher limit
```

These numbers must be configurable.

## 13. Versioning

Use:

```text
/api/v1
```

Do not make breaking changes inside the same version without a migration path.
